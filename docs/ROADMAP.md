# 通用 ar 库的范围与交付计划

MoonAr 的目标是实现完整的通用 Unix ar 库，使 MoonBit 程序可以完成归档读取、
成员访问、thin 外部引用处理、创建、编辑、格式转换与符号索引维护，并通过命令行接入
构建流程。GNU、BSD 和 Darwin 是主要兼容对象。归档比较作为构建复现和修改结果核对工具，
与读写能力共同组成完整工作流。

“完整”以以下范围和验收标准为准：支持所列格式的归档生命周期，不把全部历史 ar
变体、对象指令解码、链接器或包管理器作为交付目标。

## 功能范围

| 能力 | 交付内容 | 验收标准 |
| --- | --- | --- |
| 读取与访问 | 普通 GNU/BSD/Darwin，长名称、重名成员、原始名称字节、元数据和数据访问 | 与 GNU/LLVM 列表和提取字节一致；截断、非法数值与错误引用返回定位诊断 |
| thin 处理 | GNU thin 容器、外部引用、受调用方控制的加载、thin 创建与编辑、普通归档转换 | 与 GNU/LLVM 生成的 thin 互读；成员位于归档目录之外、缺失、变长、路径重定向时行为明确；转换后载荷与外部文件一致 |
| 创建 | GNU/BSD/Darwin 输出、确定性模式和元数据保留、长名称表、奇偶对齐 | GNU/LLVM 可读取和提取；相同输入与选项重复写出字节一致；字段超宽与资源超限返回错误 |
| 编辑 | 追加、插入、替换、删除、移动与重命名；按成员序号或名称及出现次数定位 | 对一个重名成员的修改不影响其他同名项；顺序与数据符合操作；失败保持原输入 |
| 索引维护 | 调用者提供符号映射；从受支持对象格式生成索引；布局变化后重建 GNU/BSD 32/64 位索引 | 所有目标指向重建后的成员头部；与 `nm` 的符号映射一致；替换、删除和移动后可完成链接与运行 |
| 转换与比较 | GNU/BSD/Darwin 转换、thin 物化；物理与逻辑差异 | 格式转换保持普通成员数据和指定元数据；仅布局改变时符号映射相同；保留重名身份歧义 |
| 文件与命令行 | 列表、检查、读取成员、创建、替换、删除、移动、转换和索引重建；JSON 与稳定退出码 | 临时文件写入后替换目标；失败不损坏原归档；输出路径及覆盖策略显式；脚本可核对每条操作 |

符号发现先覆盖 ELF32/ELF64 大小端的全局、弱定义及公共符号，再扩展 Mach-O
对象。COFF 双 linker-member、AIX big archive、LTO 插件、压缩 tar、对象代码/ABI 分析
以及流式处理不属于首个完整版本的范围。普通 ar 的字节成员接口适用于任意内容；
自动索引只针对明确列出的对象格式。

## 核心设计

### 区分容器字节与外部成员

普通归档的数据包含在容器内；thin 的普通成员只保存外部引用，声明大小不占用容器中的
同等字节。两者使用独立类型，避免将外部数据误当作归档内切片。thin 解析不隐式访问磁盘；
加载器接收路径与预算，调用者负责工作区根目录、文件系统链接和实际读取方式。

### 先编辑逻辑成员，再规划物理布局

编辑以普通成员序列为对象，保留重名项。名称表、头部偏移和索引均由最终成员序列重新计算。
导入带索引归档时必须显式决定索引策略；删除成员或替换对象后，不能沿用旧的符号映射。
确定性写出统一时间戳、用户/组标识和模式；保留模式按头字段宽度检查元数据。

### 以外部工具验证互操作

验收同时包含“参考工具生成，MoonAr 读取”和“MoonAr 写出，参考工具读取”。
单纯自写自读只用于回归检查，不能替代互操作。静态库还需使用真实对象，
经 `nm` 核对符号并链接执行；损坏与失败路径分别验证。
